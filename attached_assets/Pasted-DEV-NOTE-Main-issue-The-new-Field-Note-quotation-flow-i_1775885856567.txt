DEV NOTE

Main issue

The new Field Note quotation flow is partially updated, but the core pricing suggestion is not working.

Current problems

1. Clicking Suggest Price fails with the error:
   “Failed to generate suggestion”

2. The old Client-Facing Pricing block is still showing in a way that feels leftover or unfinished.

3. The quote output still does not feel like a real professional quote.

4. Taxes are not handled properly in the quote flow.

Main priority

Fix the Suggest Price engine first.
That is the critical issue.
Everything else below should support that flow.

Scope

Only work inside the Field Note quotation flow.
Do not touch attendance.
Do not touch payroll.
Do not touch schedules.
Do not touch employee hours.
Do not touch auth.
Do not touch unrelated quote systems.
Do not touch invoices unless the quote module directly depends on shared quote rendering.
Do not change anything else without approval.

1. Fix Suggest Price so it always generates when enough data exists

Problem

The user is filling out the quote form, including:
client details
property type
property details
scope
summary
internal pricing inputs

But Suggest Price still fails.

Required fix

Audit the Suggest Price backend and frontend flow end to end.

Check all of these carefully

A. Frontend request payload
Make sure all required fields are actually being sent.
Do not let the button submit partial or malformed payloads silently.

B. Validation logic
If required fields are missing, do not fail with generic toast.
Show clear inline guidance telling user exactly what is missing.

C. Backend pricing endpoint
Confirm the quote suggestion endpoint is:
receiving payload
validating correctly
not crashing on optional null fields
not failing because of property subtype mismatch
not failing because square footage is blank
not failing because some tag arrays are empty
not failing because one internal pricing field is blank

D. Fallback logic
If some optional inputs are missing, the engine must still generate a suggestion using fallback assumptions.
Do not hard fail unless truly critical data is missing.

Critical rule

Square footage must not be mandatory for suggestion.
If missing, use fallback estimate from:
property type
room counts
washrooms
kitchens
condition
frequency
estimated labor hours
crew size

E. Error visibility
Log the real failure reason in server logs.
Do not only return “failed to generate suggestion.”
Return a structured error internally so the issue can be debugged fast.

Populate what actually matches the selected service type.

Still allow optional extra display amounts for admin reference if helpful, but the client-facing quote should stay focused.
