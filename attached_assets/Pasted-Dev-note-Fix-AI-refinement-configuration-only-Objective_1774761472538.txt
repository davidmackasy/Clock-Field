What is happening

The frontend is calling the AI refinement endpoint, but the backend does not have the OpenAI API key configured.
OpenAI’s official docs say API keys must be kept secret, must not be exposed client-side, and should be securely loaded from an environment variable on the server.

Required fix

Add the OpenAI API key to server environment secrets
Ensure the backend AI refine route reads that key from the server environment
Ensure the frontend never tries to call OpenAI directly
Replace the raw config error toast with a clean professional fallback message
Keep the rest of the incident report flow unchanged

Environment configuration

Add this environment secret on the server:

OPENAI_API_KEY=your_openai_api_key_here

Do not hardcode the key in code.
Do not place the key in client-side environment variables.
Do not expose the key in browser code, logs, or network responses.

OpenAI docs explicitly say the API key is a secret and should be securely loaded from a server-side environment variable or key management service.

Backend requirements

Locate the incident report AI refinement route or service.
It likely does something like:

receives rough incident notes
calls OpenAI
returns refined structured text

Fix it so that:

Safe backend logic

Pseudo logic:

const apiKey = process.env.OPENAI_API_KEY;

if (!apiKey) {
  return res.status(503).json({

  });

If using the current OpenAI SDK, keep the call server-side and use a structured response shape so the refined incident fields come back predictably. OpenAI supports structured outputs with JSON schema, which is the right pattern for incident title, refined description, causes, and follow-up fields.
