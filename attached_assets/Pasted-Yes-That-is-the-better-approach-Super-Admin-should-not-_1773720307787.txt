DEV NOTE

Task
Add a platform-level Super Admin system and SaaS subscription management layer on top of the existing multi-business app, using the existing admin login system only.

Critical rule
Do not break, remove, rewrite, or affect anything that is already working in production.

Do not touch:

* employee clock-in
* employee clock-out
* attendance recording
* schedules
* payroll calculations already working
* request system already working
* work log already working
* timesheets already working
* employee login flow
* admin login flow
* client login flow
* company data already saved in production

This feature must be additive only.

Main goal
Create a Super Admin mode that allows selected admin accounts to manage the whole SaaS platform, all subscribed businesses, their plans, access limits, Stripe billing, platform metrics, and platform-wide business messaging.

Important update
Do not create a separate Super Admin login.
Do not create a second auth flow.

Super Admin must be implemented as an elevated permission on existing admin accounts.

That means:

* an existing admin account can be marked as super admin
* that same admin logs in through the normal admin/business login
* once logged in, if they have super admin permission, they can switch between:

  * Business Admin mode
  * Super Admin mode

System structure
There are now still 4 levels of users:

* Super Admin capable Admin
* Business Admin
* Employee
* Client

But Super Admin is not a separate account type with separate login.
It is a platform permission attached to selected admin accounts.

Product rule
A business admin manages their own company.
A super admin-capable admin can switch into platform management mode and manage the whole SaaS.

If plan does not include payroll:

* Payroll page is locked or hidden
* backend payroll endpoints reject access if called directly

Important
Do not delete existing data if a plan changes downward.
Instead:

* freeze creation of new records beyond the limit
* show over-limit warning
* require upgrade or cleanup

Part 9. Super Admin subscription controls

Super Admin mode must be able to:

* see each business plan
* see billing cycle

* see if subscription cancelled

* manually reactivate access
* manually move business between plans if needed

About auto charging cards
Do not build a random manual charge button that charges stored cards outside normal Stripe subscription logic.
Safer approach:

* let Stripe manage automatic recurring billing
* super admin can trigger a subscription resume/reactivate flow
* super admin can change plan or billing cycle
* super admin can retry failed invoices through Stripe-linked workflow

Safer business rule
Stripe auto-renews monthly/yearly by default.
Super Admin monitors, changes, suspends, or reactivates, but Stripe handles recurring charging.
