Dev note for agents
Issue:
Photo descriptions are showing correctly inside the page editor on the admin side, but they are not showing on the public generated field note link.
This must be fixed properly.
Scope only:
Fix photo description rendering on the public generated page link for Field Notes Pages.
Do not touch attendance.
Do not touch clock in / clock out.
Do not touch payroll.
Do not touch schedules.
Do not touch requests.
Do not touch authentication.
Do not touch unrelated work log features.
Do not change the current page editor flow unless directly needed for description save compatibility.
Do not break page creation.
Do not break photo upload.
Do not break public sharing.
Do not break PDF export.
Do not break existing walkthrough notes or existing public field note links.
Main goal:
Any photo description written manually or generated by AI inside the page editor must appear properly on the public generated link for that same page.
Current problem:
Admin/editor side:
Photo cards show descriptions correctly.
Public share side:
Photos appear, but the descriptions are missing.
This means one of these is happening:


The descriptions are not being saved to the correct field


The public API is not returning the description field


The public renderer is not reading the description field


The public renderer is filtering it out by section/settings


The editor and public page are using different photo models or different field names


What to investigate first:


Check the data at the database level
Take one page with known photo descriptions and confirm:
Are the descriptions actually stored in DB?
Which field name stores them?
Examples to check:
description
caption
note
aiDescription
summary
annotation


Compare admin page data vs public page data
Inspect the payload used by:
A. Admin page editor photo list
B. Public generated link photo list


Check whether the admin API returns description text but the public API does not.


Check field mapping
The editor may be reading one field and the public page may be expecting another.
Examples:
Admin reads photo.description
Public reads photo.caption
Admin saves ai_description
Public renders description only


Check page settings / visibility filters
If there is already a setting like:
show photo descriptions
include photo notes
include annotations
make sure it is enabled by default or handled correctly.
Do not silently suppress descriptions on the public page if they exist.


Required fix behavior:
If a photo on a page has a saved description, show it directly under that photo on the public generated page.
This should work for:
Manual descriptions
AI-generated descriptions
Edited AI descriptions
The public page should keep the current clean layout, but descriptions must render consistently under or with each image.
Implementation requirements:


Use the same source of truth
Do not create a second description field for public pages.
Use the exact same saved photo description field already used by the editor.


Ensure public API returns description fields
For the public page endpoint, include the photo description-related fields in the serialized response.
At minimum return:
photo id
image url
sort order
label/type if any
description/caption text


Ensure public renderer displays the text
Render the description below each photo in a clean, readable way.
Keep spacing professional.
Do not let text overlap images.
Do not stretch cards awkwardly.
Support variable text length.


Preserve order
Descriptions must stay attached to the correct photo.
Do not mismatch description-to-image pairing.
Respect current photo ordering.


Do not affect photos with no description
If a photo has no description, do not render an empty block.
Only show the text when a saved description exists.


Maintain current public styling
Do not redesign the whole public page.
Only add the missing description rendering cleanly and safely.


Important compatibility requirement:
This fix must work for both:
New manual Pages
Walkthrough-generated pages if they also carry per-photo descriptions
If older field notes already support captions in another way, do not break them.
Testing required:


Create a page with manually written photo descriptions


Open the public generated link


Confirm every described photo shows the correct description


Generate AI photo descriptions


Open the public link again


Confirm AI descriptions also show


Edit an existing description


Refresh public link


Confirm updated description appears


Confirm photos without descriptions do not show empty text blocks


Confirm existing public field notes without descriptions still look normal


Confirm PDF export still behaves correctly if it already includes descriptions


Acceptance criteria:
Photo descriptions visible in the page editor also appear on the public generated field note link
Descriptions stay paired with the correct images
Manual and AI-generated descriptions both work
No unrelated feature is changed or broken
Priority:
High
This is part of the core page documentation experience. If users write or generate photo descriptions, those descriptions must carry through to the public page properly.
