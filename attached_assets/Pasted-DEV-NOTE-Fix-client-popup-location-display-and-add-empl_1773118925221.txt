Biweekly reset logic

This is the key part.

Required behavior
Payroll history must be grouped into 14-day pay periods.
Once a pay period ends, the next one starts fresh.

Important rule
Pay periods should not just be random calendar chunks.
They must be based on the company or employee pay period start logic.

Safe MVP rule
Use company-level payroll cycle start date from settings.
Then generate continuous 14-day pay periods from that anchor date.

Example
If company pay cycle starts on March 1:
Period 1 = Mar 1 to Mar 14
Period 2 = Mar 15 to Mar 28
Period 3 = Mar 29 to Apr 11

All attendance/time entries must be grouped into the correct biweekly period.

If settings do not yet have this
Add one simple setting:
Payroll cycle start date

Do not make this complicated.
One company-wide pay cycle start date is enough for now.

Payroll history calculations

For each employee and each pay period:
sum regular worked hours
sum overtime hours
calculate regular pay
calculate OT pay
calculate gross pay
calculate tax = gross * 0.05
calculate net pay = gross - tax

Recommended formulas
regular_pay = regular_hours * hourly_rate
ot_pay = ot_hours * overtime_rate if enabled, else 0
gross_pay = regular_pay + ot_pay
tax_amount = gross_pay * 0.05
net_pay = gross_pay - tax_amount

Rounding
Round monetary values to 2 decimals only at display/output layer.

Data source and storage

Do not create a totally separate payroll truth table unless needed.
This can be derived from attendance/time entries plus employee rate plus pay cycle setting.

Use:
time_entries
employees/pay_rates
company payroll settings
