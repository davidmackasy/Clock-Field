DEV NOTE: FIX SUPPLIES PHOTO UPLOAD ERROR IN ADMIN WITHOUT BREAKING OR AFFECTING ANYTHING ELSE

Important:
Do not touch anything else.
Do not refactor unrelated pages.

Only fix the Supplies photo upload/update flow in admin.
Production-safe only. No destructive changes.

Issue:
When updating or uploading a supply photo from the admin Supplies page, the frontend throws a runtime error and the upload fails.

Current affected flow:
Admin > Supplies > open/edit a supply item > click Update Photo / upload photo > runtime error overlay appears

Goal:
Fix the supply photo upload so admin can:

Upload a photo when creating a supply
Update/replace a photo when editing a supply
Save changes successfully
See the new photo reflected immediately on admin side
Ensure the updated photo also reflects correctly on cleaner side where applicable

Main requirement:
Fix only this upload error cleanly without breaking anything else.

Frontend upload handler for Supplies
Check the exact component handling:

save payload submission

Implementation guidance

Normalize the image field
Use one consistent field across create, update, read, and render.
Example:
imageUrl

If backend already uses another field, keep compatibility, but normalize safely in the frontend.

Add null-safe guards
Before rendering or updating preview:
check file exists
check uploaded response exists
check URL exists

Never assume shape blindly.

Keep preview state isolated
Use separate state for:

Revoke object URLs if used
If using URL.createObjectURL for previews, clean it up properly to avoid weird state issues.
Preserve old photo if upload fails
If a new photo upload fails, do not wipe out the existing saved photo in the UI.
Error handling
Instead of crashing with runtime error overlay, show a clean inline or toast error such as:

Do not expose raw runtime error to the admin user.

Keep mobile and desktop working
This fix must work on both desktop admin UI and mobile admin UI.
