DEV NOTE: Fix Hiring Package Upload Failed Connection Error
Issue:
The upload UI is now triggering, but every upload fails with:
Upload failed. Please check your connection and try again.
This means the file picker and frontend upload handler are working, but the request is failing after upload starts.
Most likely causes:
Wrong upload API route
Backend route not registered
Public route blocked by auth middleware
Multipart/form-data not being parsed
Request body/file too large
Backend returning 401, 403, 404, 413, or 500
Frontend catch block is hiding the real backend error
Storage upload is failing
CORS or Replit route/proxy issue
Document type mismatch between frontend and backend
Scope:
Only fix Hiring Package document uploads.
Do not touch anything else.
Do not change policies.
Do not change signature.
Do not change personal info.
Do not change Publications outside Hiring Package.
Do not touch Agreements, Proposals, Forms, Field Notes, Auth, Stripe, Payroll, Attendance, or Employee app.

Check browser Network tab first


Open DevTools > Network.
Try uploading one small PDF under 1 MB.
Check the upload request:
Request URL
Request method
Status code
Response body
Fix based on status:
404:
Frontend is posting to the wrong route or backend route does not exist.
401 or 403:
Upload route is protected by auth middleware. Public hiring package uploads must validate token, not require login.
413:
Request body/file size limit is too low. Increase multipart/server/proxy limit to 100 MB.
415:
File type validation is rejecting the file.
500:
Backend route exists but upload/storage/database save is failing.


Use one exact upload route


Standardize the route everywhere.
Frontend must POST to:
/api/public/hiring-package/:token/upload-document
Backend must register the exact same route:
POST /api/public/hiring-package/:token/upload-document
Do not use mixed route names like:
/api/public/hiring-packages/:token/upload
/api/hiring-package/:token/documents
/api/public/hiring-package/:id/upload
Use one route only.


Public upload route must not require login


This route is used by employees from a public link.
Do not use admin auth middleware on this route.
Correct logic:
Validate public token
Find hiring package
Find or create submission
Allow upload
Wrong logic:
Require logged-in admin
Require employee account
Require session auth
Block public route because token is not an authenticated user


Confirm frontend FormData is correct


Frontend upload must send multipart/form-data.
Do this:
const formData = new FormData()
formData.append("file", file)
formData.append("documentType", documentType)
await fetch(/api/public/hiring-package/${token}/upload-document, {
method: "POST",
body: formData
})
Do not manually set Content-Type.
Wrong:
headers: { "Content-Type": "application/json" }
Wrong:
body: JSON.stringify({ file })
The browser must set the multipart boundary automatically.


Backend must parse multipart/form-data


If using Express, use multer or equivalent.
Example logic:
upload.single("file")
Make sure backend reads:
req.file
req.body.documentType
req.params.token
If req.file is undefined, the multipart parser is not connected correctly.
