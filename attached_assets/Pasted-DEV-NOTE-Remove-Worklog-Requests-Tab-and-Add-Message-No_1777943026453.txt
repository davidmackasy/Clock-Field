Part 2: Add message notification badges

Current issue

Users have to guess whether they received a new message.

There is no clear unread message count on the navigation/sidebar/bottom icon.

Required change

Add unread message notification badges for Messages.

Show the number of unread messages or unread conversations.

This should work for:

Admin

Employee

Client, if client portal has Messages

Badge examples:

1

2

3

9+

Required locations

Admin side:

Sidebar Messages nav item

Mobile hamburger menu if admin mobile navigation exists

Any top nav message icon if available

Employee side:

Bottom navigation Messages icon

Messages page header if useful

Action/hamburger menu if applicable

Client side:

Messages nav item or Messages button

Client portal action area if applicable

Badge behavior

If user has 0 unread messages:

Do not show a badge.

If user has 1 unread message:

Show badge with 1.

If user has 2 unread messages:

Show badge with 2.

If user has more than 9:

Show 9+.

Badge should update when:

A new message is received.

A conversation is opened/read.

The user sends a reply and the other side becomes unread.

Badge count definition

Use unread conversations if easier and cleaner.

Recommended:

Count conversations where the current user has unread messages.

Not total unread individual messages unless the app already tracks that.

Example:

Admin has 3 conversations with unread replies.

Badge shows 3.

Employee has 1 unread admin reply.

Badge shows 1.

Client has 2 unread admin replies.

Badge shows 2.

Unread logic requirements

Track unread per participant.

Opening a conversation should mark it read for the current user.

Sending a message should mark it unread for the receiver, not for the sender.

A user should not get an unread badge for their own sent messages.

Required backend check

Inspect current message/conversation tables.

Use existing unread/read logic if it exists.

If missing, add safe fields only.

Possible safe structure:

conversation_participants:

conversation_id

participant_type: admin, employee, client, management

participant_id

last_read_at

unread_count, optional

Alternative:

messages:

read_by_admin_at

read_by_employee_at

read_by_client_at

Only use this if current schema is simpler.

Preferred approach:

Use participant-level last_read_at.

Unread count query:

Count conversations where latest message is newer than current participant last_read_at and latest message sender is not current user.

Security requirements

Unread counts must be scoped by business.

Admin only sees unread messages for their business.

Employee only sees their own messages.

Client only sees their own messages.

No cross-business counts.

No client should see another client’s unread messages.

No employee should see another employee’s unread messages.

UI badge requirements

Badge should be small, clean, and professional.

Use ClockField blue or red/orange depending on existing style.

Place badge on:

Admin Messages sidebar item

Employee Messages bottom nav icon

Client Messages item/button

Badge should not break layout.

Badge should work on desktop and mobile.

Badge should not cover labels badly.

Suggested visual style

Small circle or pill.

Min width: 18px.

Height: 18px.

Font size: 11px or 12px.

Position: top-right of icon or end of sidebar row.

Examples:

Messages 3

Messages with small badge beside label

Bottom nav icon with badge at top-right

Part 3: Notifications refresh behavior

Badge should update without needing a full logout/login.

Acceptable options:

Use existing polling system if already used.

Refresh count when user navigates.

Refresh count after message send.

Refresh count after opening/closing messages.

If real-time subscriptions already exist, use them.

Do not build a risky new real-time system unless already supported.

Recommended safe approach:

Fetch unread count when app shell loads.

Fetch unread count every 30 to 60 seconds while user is active.

Fetch unread count after sending a message.

Fetch unread count after opening a conversation.

Do not over-poll aggressively.
