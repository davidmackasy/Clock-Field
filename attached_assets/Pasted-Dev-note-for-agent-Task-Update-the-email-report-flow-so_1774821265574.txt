Dev note for agent

Task

Update the email report flow so that when a client or employee receives a report by email, the link opens a public secure report page directly. They must be able to review the report and sign it without being forced to log in.

This applies only to reports sent through the email delivery flow.

Do not break:

* current in-app report delivery
* current login-based account access
* finalize flow
* archive flow
* print / PDF flow
* current report generation
* current report data structure
* current admin flow
* existing auth
* anything else outside this feature

Do not touch unrelated logic. Only extend the email report access flow and signature experience for emailed reports.

Main goal

When a report is sent by email:

* recipient clicks View Report or Review and Sign
* link opens a secure public report page
* recipient can read the report without signing in
* recipient can sign directly on that page
* recipient can submit signature
* signature is saved to the correct report
* report updates properly after signing

Important behavior difference

Keep both flows:

1. In-app flow
   User logs in and sees reports in their account as usual

2. Email flow
   User clicks secure emailed link and is taken to a public secure report page with no login required

Do not merge these in a way that breaks current account access.
This is an added email-access route only.

Public secure report link requirements

Do not use an open public URL with raw IDs.
Do not expose report data insecurely.

Use a secure tokenized access link for emailed reports.

Recommended pattern

* generate one secure access token per recipient per report delivery
* token should be long, random, unguessable
* token should map to:

  * report id
  * recipient type
  * recipient email
  * intended permissions
  * expiration or validity state if needed
  * signature eligibility
  * usage timestamps

Recommended permissions for token

* read report
* download report PDF if allowed
* sign report if signing is required
* submit signature once authorized by token

Do not expose other reports.
Do not allow token reuse across unrelated reports.

Suggested link example
/public/reports/access/:token

or

/reports/public/:token

Use whatever fits current routing without disrupting existing routes.

Email CTA behavior

Current issue
The email should not redirect them to login before seeing the report.

Required behavior
If the user arrives through a valid public report token:

* bypass login requirement for that specific report page
* open report directly
* allow review
* allow signing if allowed

If token invalid or expired:
Show a clean message like:
This report link is no longer available. Please contact the sender for a new link.

Do not show raw backend errors.

This page should:

Signature requirements

This matters a lot.

Do not make signature name-only unless that is only the typed signature mode.
The signing experience must allow an actual signature.

Support these signature methods on the public report page:

* draw signature with finger or mouse on a signature pad
* type name and render it as signature-style text
* optional clear/reset button
* save and submit signature

Preferred implementation
Support both:

1. Draw signature
2. Type signature

Recommended UI tabs or toggle

* Draw
* Type

Draw mode

* signature pad canvas
* works on mobile with finger
* works on desktop with mouse
* clear button
* smooth strokes
* proper sizing

Type mode

* recipient types full name
* system renders it in a signature-style font preview
* they confirm it before submit

Do not use plain input text as the final visible signature.
If typed, render it into a signature-style display before saving.

Optional small agreement text
By signing, you confirm you have reviewed this report.

If current legal/compliance wording already exists, reuse it.

Signature data to save

When signature is submitted, store:

* report id
* recipient type
* recipient email if from public token flow
* signer name
* signature method used
* signature image or vector data for drawn signatures
* typed signature rendered value if typed mode used
* timestamp
* IP or device metadata only if already acceptable in your system
* token id or public-access record reference
* signed status

Do not overwrite unrelated signatures.
If report supports multiple signers, preserve that model.

Important
If a client signs, it should save as client signature.
If an employee signs, it should save as employee signature.
Do not mix recipient roles.

Signing rules

Before allowing sign:

* validate token
* validate report exists
* validate recipient type allowed to sign
* validate report is signable
* validate this signature has not already been finalized if one-time sign only

After successful sign:

* show clean success screen
* optionally mark report status as signed or partially signed based on your existing logic
* optionally email confirmation later if needed, but do not build that unless already easy

Success page example
Report signed successfully.
Your signature has been recorded.

Buttons:

* Download PDF
* Close page

If already signed
Show:
This report has already been signed.

Do not allow duplicate signing unless your report model explicitly supports re-signing.

Security and token control

Very important.

The public email link must be secure.
Do not make all reports public just because email sending exists.

Recommended controls

* recipient-scoped token
* optional expiration window
* revocation support if report is re-sent
* signed/used tracking if needed
* access only to that one report
* only the allowed actions for that recipient

Recommended backend data model idea

report_public_access_tokens

* id
* report_id
* recipient_type
* recipient_email
* token_hash
* permissions
* created_at
* expires_at nullable
* revoked_at nullable
* last_accessed_at nullable
* signed_at nullable
* created_by admin id

Never store raw token in plaintext if avoidable.
Prefer storing hash and only emailing the raw one-time token.
