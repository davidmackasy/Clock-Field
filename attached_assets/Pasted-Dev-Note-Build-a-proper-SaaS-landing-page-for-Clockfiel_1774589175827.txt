Dev Note: Build a proper SaaS landing page for Clockfield inspired by CompanyCam, while keeping Clockfield’s own features, flows, and branding

Goal

Build a true marketing landing page for Clockfield that feels professional, modern, and conversion-focused, similar in structure and usability to CompanyCam’s website. The landing page must look like a real SaaS homepage on desktop, tablet, and mobile, while still promoting Clockfield’s actual features and workflows. CompanyCam’s current site uses a clear top navigation, strong hero section, repeated calls to action, feature groupings, trust/review elements, pricing access, and direct paths to Log In and Free Trial/Signup, which is the structural reference for this project.

Critical instruction

Do not break or affect anything else that is already working in the app.

Do not modify existing authenticated app logic, dashboard logic, employee logic, admin logic, registration logic, sign-in logic, or public link/report logic unless it is strictly required for routing from the landing page.

Do not rename or move any existing working route without approval.

Do not change database logic for users, employees, admins, teams, tasks, reports, attendance, payroll, reviews, or messaging.

Only add what is needed to introduce a proper public-facing landing page and connect it safely to the existing auth flows.

High-level product behavior

Right now the app needs a public homepage that acts as the main marketing entry point for new visitors.

The landing page should:

Explain what Clockfield does in a clean, user-friendly way
Show the key value of the product quickly
Present the product as a SaaS platform for commercial cleaning and field operations
Make it easy to go to Sign Up
Make it easy to go to Log In
Make it easy for employees to access their own entry point if that exists
Work properly on desktop, tablet, and mobile
Feel like a real landing page, not like an internal app screen

CompanyCam’s homepage structure is a good reference because it clearly separates public marketing content from app login and trial entry, and it repeats primary CTAs like Log In, Start a Free Trial, Pricing, Reviews, and Demo-style actions across the page.

Main implementation requirement

Build a new public marketing landing page as the root public entry point, likely at:

/

If / is already being used by the product in a way that would disrupt the current user experience, do not break it. In that case:

Create the landing page in a safe new route first, such as /home or /landing
Then wire the root route to it only after confirming existing app behavior remains intact
Preserve current logged-in redirects exactly as they are

Routing behavior required

Public visitor behavior

If user is not authenticated:

Visiting / should show the new landing page
Clicking Sign Up should go to the existing business registration/signup flow
Clicking Log In should go to the existing login flow
Clicking Employee Access should go to the employee login or employee entry flow if one exists
Clicking any CTA should route cleanly without errors

Authenticated user behavior

If business/admin user is already authenticated:

Do not trap them on the landing page
Either show a top-right “Go to Dashboard” button, or auto-redirect them to their normal authenticated destination if that is already your current app behavior
Keep current session logic intact

If employee is already authenticated:

Keep employee routing intact
Do not accidentally redirect employees to the business dashboard
Preserve their current role-based destination

Required pages and path connections

The landing page must cleanly connect to:

Registration page
Sign-in page
Employee sign-in or employee access page
Pricing page if one exists
Contact/demo/request info page if one exists
App/dashboard after authentication

Agents must audit all current auth-related routes and confirm the correct destinations before wiring buttons.

Do not hardcode guessed routes if route names already exist elsewhere in the app. Reuse existing route constants or central route config if available.
