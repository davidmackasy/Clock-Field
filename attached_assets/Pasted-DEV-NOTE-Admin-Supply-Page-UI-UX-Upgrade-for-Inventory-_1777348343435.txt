DEV NOTE: Admin Supply Page UI/UX Upgrade for Inventory and Requests

Project: Clockfield
Area: Admin Panel → Supplies
Scope: Inventory tab and Requests tab only
Goal: Improve the UI so products feel like items displayed on a shelf, make products easier to scan and click, show them in a clean grid of 4 per row, and reduce the need to scroll to the bottom to find cleaner requests.

Critical instruction

Do not break or change any working logic.

Do not change the current backend behavior.

Do not change database relationships unless absolutely needed for display only.

Do not change how supplies are created.

Do not change how supplies are assigned.

Do not change how restock works.

Do not change how view works.

Do not change how requests are submitted.

Do not change statuses, filters, or current workflows.

Do not change anything outside the admin Supplies area.

This task is UI/UX only for the admin side under Supplies, specifically the Inventory and Requests experience.

Main problem

Right now the admin supply pages work, but the UI does not feel organized or easy to scan.

The current issues are:

The Inventory page does not feel like a product shelf.
Products do not feel visually organized enough.
The layout does not make it easy to scan many products quickly.
The cleaner requests feel buried too far down the page.
Admin has to scroll too much to get to important requested items.
The layout feels flat and more like a plain list than a shelf display.

What we want

We want the admin Supplies page to feel more like products placed on shelves.

That means:

Products should be displayed in a structured grid.
Inventory items should show in 4 cards per row on desktop.
The cards should feel like shelf items, clean and organized.
Requests should also be easier to access and visually organized.
Admin should not need to scroll all the way to the bottom just to see cleaner reports or requests.
Keep the same actions and the same flows, but improve how they are presented.

Required UI direction

Inventory page should look like a shelf

Update the Inventory tab UI so items appear as product cards arranged like items on a shelf.

Each product should appear in a compact but clean card.

Each card should include:

Product image
Product name
Category
Location if relevant
Stock count
Unit price
Value
Status badge
Cleaner assigned if relevant
Quick actions or click-to-open actions

Visual style:

Cards should feel like products sitting on a shelf.
Use even spacing.
Use clean card edges.
Use a subtle border or shadow.
Use consistent image area.
Keep the cards aligned.
Make the products feel more premium and easier to scan.

Do not make the cards too tall.
Keep them compact enough so 4 can fit in a row on desktop.

Grid layout requirement

Inventory tab:

Desktop:
Show 4 cards per row.

Large desktop:
If it still looks clean, allow 4 cards per row with slightly wider spacing.
Do not go beyond what looks good visually.

Tablet:
Show 2 to 3 cards per row depending on width.

Mobile:
Show 1 or 2 per row depending on current responsive layout.

Requests tab:
Use the same card-based shelf style so the page feels consistent.

Desktop:
Use 4 per row if possible.

Tablet:
2 to 3 per row.

Mobile:
1 to 2 per row.

Important:
Do not break the existing responsive layout on smaller screens.

Requests should not be buried at the bottom

This is a key problem.

Right now the admin has to scroll all the way to the bottom to see what the cleaner requested.

That should be improved.

Required change:

Make the Requests tab a proper first-class tab with its own full card grid layout.

The Requests tab should show all request-related items clearly, not as a bottom section buried under assigned products.

Also add a summary near the top of the Supplies page or within the Requests tab:

Pending requests count
Unresolved cleaner reports count
Low stock count if already available
Out of stock count if already available

This helps the admin know what needs attention immediately.

If there is already a “Cleaner Reports” section, keep its logic, but surface the important count higher so the admin can click directly into it without scrolling.
