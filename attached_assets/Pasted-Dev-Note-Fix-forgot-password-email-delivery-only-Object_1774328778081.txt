Current issue observed

The forgot password flow appears to generate the request, but the email is not arriving. The Mailgun event log shows Yahoo rejected the message because the visible From header domain is clockfield.ca while the email is being sent through the Mailgun domain mg.clockfield.com. The error shown was:

“Message permanently deferred due to unresolvable From header domain clockfield.ca”

The log also shows:

Mailgun sending domain: mg.clockfield.com
Visible From header: Clockfield <noreply@clockfield.ca>

This strongly indicates a sender-domain alignment/configuration issue in the outbound email setup, not necessarily a reset-token logic issue. Mailgun sending is domain-based, and Yahoo specifically rejects messages when the From domain fails its checks.

Most likely root cause

The Mailgun request is using the verified Mailgun domain:

mg.clockfield.com

But the visible From address is using:

noreply@clockfield.ca

This mismatch is likely causing Yahoo to reject the message. The safest immediate fix is to align the visible From address with the verified Mailgun sending domain already in use:

change From to Clockfield <noreply@mg.clockfield.com>

Do not switch domains again unless explicitly approved.

Required fix

Find the backend forgot-password email sending function and update only the sender configuration for that reset email.

Replace:
Clockfield <noreply@clockfield.ca>

With:
Clockfield <noreply@mg.clockfield.com>

Keep the Mailgun request domain as:
mg.clockfield.com

Mailgun’s Messages API sends in the context of the domain used in the request path, and verified domain setup depends on SPF/DKIM configuration for the sending domain.

Safe code example

If the current implementation is Java and uses Unirest, the forgot-password sender should look like this pattern:

public JsonNode sendResetPasswordEmail(String userEmail, String resetLink) throws UnirestException {
    String apiKey = System.getenv("MAILGUN_API_KEY");

    HttpResponse<JsonNode> request = Unirest.post("https://api.mailgun.net/v3/mg.clockfield.com/messages")
        .basicAuth("api", apiKey)
        .queryString("from", "Clockfield <noreply@mg.clockfield.com>")
        .queryString("to", userEmail)
        .queryString("subject", "Reset your Clockfield password")
        .queryString("text", "Click the link below to reset your password:\n\n" + resetLink)
        .asJson();

    return request.getBody();
}

This code belongs in the app backend email sending logic, not in MongoDB.
