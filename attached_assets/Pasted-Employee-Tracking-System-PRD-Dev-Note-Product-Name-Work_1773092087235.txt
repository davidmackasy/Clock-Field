Employee Tracking System PRD + Dev Note
Product Name

Working name: Employee Tracking System Category: Workforce Operations Web App Product type: Mobile-first responsive web app with native-app feel on phones and full dashboard on desktop

1. Product Vision

Build a workforce operations system for service businesses that helps employers manage employees, schedules, attendance, worked hours, payroll estimation, proof of work, client requests, and service reporting in one place.

This product is not just a time tracker.

It is a business operations platform with 3 connected user roles:

Admin / Employer

Employee

Client

The app must feel simple for field workers on mobile and powerful for managers on desktop.

2. Core Objective

Give employers one system where they can:

create employee schedules

let employees see their assigned work schedule

let employees clock in and clock out against scheduled shifts

track lateness, early clock-ins, missed shifts, and missing clock-outs

calculate daily, weekly, monthly, and pay-period hours

estimate payroll based on employee hourly rates

collect before and after photos and service notes

allow clients to view approved service reports and submit requests

3. Primary Business Use Case

This system is ideal for:

cleaning companies

maintenance companies

field service businesses

janitorial companies

property care teams

contractors with mobile employees

The strongest use case is companies that need:

attendance accountability

proof of work

client visibility

operational reporting

4. Main Problems Being Solved

Current pain points:

employers do not know who is on time or late in real time

employees forget to clock in or clock out

schedules are unclear or scattered in messages

payroll estimation is manual and slow

work proof photos are disorganized

client requests are handled in too many places

clients cannot easily see service completion details

This platform solves all of those inside one connected system.

5. Product Principles

The agent must follow these principles while building:

Mobile first Employees and clients will mostly use phones. The mobile UI must feel like a native app.

Admin clarity Employers need operational visibility fast. The dashboard must surface the important issues first.

Schedule-driven workflow Scheduling is core. Employees should see what they are scheduled to work, and time tracking should connect to that schedule.

Proof of work Photos and notes are first-class features, not add-ons.

Role safety Each role sees only what they need.

Clean structure Do not overbuild HR tools, accounting tools, or chat in MVP.

Stability Do not build features in ways that break attendance logic, schedule logic, or reporting flows.

12. Core Business Logic
12.1 Clock-In Rules

employee must be authenticated

employee must not already have an active time entry

if there is a scheduled shift within allowed time window, attach clock-in to that shift

if multiple valid shifts exist, prompt employee to select one

if no valid shift exists, allow or block unscheduled clock-in based on company setting

start live timer immediately

12.2 Clock-Out Rules

employee must have active time entry

save clock-out timestamp

calculate worked duration

subtract breaks

compare against schedule

mark flags if late, early, overtime, or incomplete

if report is required, optionally prevent final completion until report is submitted

12.3 Shift Compliance Rules

late if clock-in exceeds shift start + grace period

early clock-in if clock-in occurs before allowed window

no-show if shift passes with no clock-in

early departure if clock-out happens before scheduled end threshold

overtime if worked time exceeds expected threshold

12.4 Report Rules

if required report is enabled for shift, report must be submitted before shift is considered fully complete

if required photos are missing, report status becomes incomplete or needs revision

admin approves client-visible reports

12.5 Payroll Rules

payroll uses approved or completed entries based on company settings

payroll is filtered by pay period

calculate regular pay first

calculate overtime if enabled

show gross estimate only in MVP

20. Final Build Instruction for the Agent

Build a mobile-first workforce operations web app with 3 roles: admin, employee, and client. Admins can manage employees, clients, locations, schedules, attendance, payroll estimates, reports, and requests. Employees can log in, view their assigned work schedule, clock in and out against scheduled shifts, run a live timer, submit reports with photos and notes, and view their own hours and attendance. Clients can log in, view approved service reports and photos, and submit service requests or issues. The system must connect schedules to time tracking, compare scheduled time to actual time, flag late or missed shifts, calculate worked hours across day, week, month, and pay period, and estimate payroll using employee hourly rates. The app must feel native on mobile and clean and professional on desktop.
