Dev note: Fix incident report preview, print, and download view only

Objective

Fix the incident report preview/export experience so users can properly preview, print, save, and download the document.

Right now the preview is broken and unprofessional because the print dialog is showing the full Reports page behind the document, the report preview is tiny and awkward, and the printable area is not isolated correctly.

This task is only about fixing the incident report preview, print, and download presentation.

Critical instruction

Do not touch anything else.

Do not change incident report fields.
Do not change report workflow.
Do not change AI refinement.
Do not change branding logic except where needed for the preview container to render correctly.
Do not change unrelated reports.
Do not change auth, settings, dashboard, or other pages.
Do not refactor unrelated code.
If anything outside this exact scope is needed, ask for approval first.

Main problem

From the screenshot, the current print/download behavior is wrong because:

the full Reports page is still visible behind the printable document
the document preview is too small and awkward
the browser print dialog is treating the whole app screen as the print source instead of only the incident report
the report preview does not feel like a dedicated printable document
save/download/print cannot be trusted because users cannot clearly see what is being exported

This means the print source is not isolated properly.

Expected behavior

When user clicks preview, print, save as PDF, or download for an incident report:

only the incident report document should be rendered as the print source
the rest of the Reports page and app UI must not appear
the preview should look like a real A4 document
if the report is multiple pages, it should continue cleanly
the user should be able to clearly see the document content before saving or printing

Main implementation goal

Create a dedicated incident report print/export view so only the report document is printed or exported.

Do not print the live dashboard page behind it.
Do not rely on printing the whole current screen/modal.
Do not let the report sit inside the normal page layout during print/export.

Most likely cause

The current implementation is probably doing one of these:

calling window.print() from the main Reports page without isolating the printable content
printing a modal overlay that still sits inside the full page DOM
hiding some UI, but not enough
using a preview container inside the dashboard instead of a dedicated print document
not applying scoped print CSS for the report-only view

That is why the preview looks like a manufactured function instead of a real document.
