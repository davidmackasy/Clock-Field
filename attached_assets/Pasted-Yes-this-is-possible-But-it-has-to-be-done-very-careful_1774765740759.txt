Yes, this is possible.

But it has to be done very carefully.

You are right to be cautious because timezone work can break schedules, attendance, payroll summaries, date grouping, and “today / tomorrow” logic if it is done the wrong way.

The safe answer is this:

You should not switch the whole app blindly from “global time” to “local time” everywhere at once.

The correct way is to keep one stable source of truth for stored timestamps, then convert and display them using the company’s selected timezone. That way, attendance records and existing data stay safe, while schedule display and day boundaries become correct for each business.

Best safe approach

Keep stored timestamps consistent in the database
Use UTC for storage if that is already how the system works.
Add a company-level timezone setting
Example:
America/Winnipeg
America/Vancouver
America/Toronto
Use that selected company timezone only for:
schedule creation
schedule display
“today” and “tomorrow” grouping
day-start and day-end logic
report display dates where appropriate
Do not rewrite old attendance math blindly
Attendance and worked-hours calculations should continue using stored timestamps, but the displayed day bucket should be interpreted in the company timezone.

That is the safe way.
