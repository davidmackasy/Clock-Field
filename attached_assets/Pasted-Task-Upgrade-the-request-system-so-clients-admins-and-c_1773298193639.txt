8. ADMIN TO CLIENT FORWARD / LINK FLOW

You mentioned admin may want to send cleaner-found issues to the client.

Best safe design
Do not literally move one request between users.
Instead allow admin to create or link a client-visible request from a cleaner request.

Recommended approach
From admin request detail:
button:
Create Client Update

This can:

create a linked client-facing request
or

mark selected admin reply as visible to client if the client is attached to that location

Simplest safe MVP
Add a field on request:
visibility_scope

Possible values

admin_only

admin_and_client

admin_and_employee

all_related_parties

Cleaner-created requests default:

admin_and_employee

Client-created requests default:

admin_and_client

Admin can choose whether a reply is visible to client.
This prevents leaking internal notes.

This is important.

Upgrade the request system into a threaded issue communication flow for clients, admins, and cleaners.
