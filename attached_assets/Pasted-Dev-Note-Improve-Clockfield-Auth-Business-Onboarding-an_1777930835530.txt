Role-Based Redirect Rules

After login:

Business owner/admin:
Go to business dashboard or current subscription/paywall flow.

Supervisor/manager:
Go to their existing management dashboard based on current role logic.

Employee/cleaner:
Go to employee dashboard, schedule, or current employee home page.

New business owner:
Go through onboarding first, then continue into the existing paywall/subscription/dashboard flow.

Do not change permissions.
Do not grant employees admin access.
Do not change business owner role logic.

Stripe and Paywall Safety

This is very important.

Do not touch:
Stripe checkout
Stripe customer IDs
Stripe webhook
Subscription status
Plan checks
Trial logic
Payment success redirect
Existing paywall conditions
Billing page
Current subscribed user access

The onboarding must sit before or beside the existing flow, not replace it.

Correct behavior:
User registers business.
User completes onboarding.
Existing app checks subscription/trial/paywall.
User sees the correct billing or dashboard state based on current logic.

Wrong behavior:
User registers and gets free access by accident.
Employee sees billing page.
Onboarding skips Stripe.
Existing customers are asked to onboard again.
Paid users lose access.

Existing Business Protection

Do not force existing businesses through the new onboarding unless they have no onboarding data and it is safe.

Existing businesses should:
Still log in normally.
Keep all data.
Keep current subscription.
Keep employees.
Keep schedules.
Keep reports.
Keep settings.
Not be interrupted by the new onboarding.

For existing businesses, the new checklist can appear as optional only if it does not block work.
