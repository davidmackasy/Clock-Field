Dev Note: Fix Booking AI Estimate + Apply Estimate to Quote Without Touching Anything Else
Goal
Fix the Booking AI Estimate flow only.
Current issue:
When clicking Get AI Estimate, it fails with:
Failed to execute 'json' on 'Response': Unexpected token '<', "<!DOCTYPE"... is not valid JSON
This means the frontend expects JSON, but the backend is returning an HTML error page instead of a valid JSON response.
Also fix the quote flow so that when an estimate is successfully generated, the estimate values are automatically applied to the quote draft, while still allowing the admin to edit everything before sending.
Do not change or affect anything else.
Do not touch:
Schedule logic
Attendance
Clock in / clock out
Clients
Employees
Field Notes
Work Reports
Public report links
Payroll
Training Hub
Public booking form structure unless required for estimate input
Existing quote email system unless only connecting the quote data safely
Main Fix 1: AI Estimate API must always return JSON
Find the endpoint used by the Get AI Estimate button.
Example:
POST /api/bookings/:bookingId/estimate
or whatever current booking estimate endpoint exists.
The issue is likely one of these:
Wrong API route
Backend route missing
Frontend calling the wrong URL
Auth/session redirect returning HTML
Server error returning Vite/HTML error page
AI service error not caught
Response is not JSON but frontend still calls response.json()
Fix requirement:
The estimate endpoint must always return JSON.
Success example:
{
"success": true,
"estimate": {
"estimatedHours": 4,
"suggestedWorkerCount": 2,
"suggestedLowPrice": 280,
"suggestedHighPrice": 420,
"recommendedPrice": 350,
"minimumPriceWarning": "Do not charge below $260 for this scope.",
"suggestedChecklist": [
"Clean kitchen",
"Clean bathrooms",
"Vacuum floors",
"Mop hard floors",
"Remove garbage"
],
"suggestedSupplies": [
"All-purpose cleaner",
"Disinfectant",
"Garbage bags",
"Mop",
"Vacuum"
],
"summary": "Residential cleaning request with high priority. Estimate is based on the provided home details and requested service type."
}
}
Error example:
{
"success": false,
"message": "Estimate could not be generated because service type or property details are missing."
}
Do not return HTML.
Do not let frontend receive <!DOCTYPE html> from this endpoint.
Main Fix 2: Frontend must handle non-JSON responses safely
Update the Get AI Estimate frontend logic.
Before calling response.json(), check the response content type.
Required logic:
Call estimate endpoint.
Check response.ok.
Check content-type includes application/json.
If not JSON, read response.text().
Show a clean error message.
Log full raw response only in console for debugging.
Do not crash the UI.
User-facing error should be clean:
Estimate could not be generated. Please check the booking details and try again.
Not:
Unexpected token '<'
