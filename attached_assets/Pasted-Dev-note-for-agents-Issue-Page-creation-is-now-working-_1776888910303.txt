The page opens correctly.
The user goes to Photos.
They choose a photo.
Upload fails and shows a red toast with the raw filename:
“Failed to upload 8791b9a9-4315-49eb-a953-d2e606e75415.png”
This must be fixed without changing anything else that is already working.
Scope only:
Fix photo upload for Field Notes Pages
Fix only the new page photo upload flow
Do not touch attendance
Do not touch clock in / clock out
Do not touch payroll
Do not touch requests
Do not touch schedules
Do not touch authentication

Do not break existing walkthrough note photo capture

Do not break reports/documents/files tabs
Main goal:
Make photo upload inside a Page work reliably and attach uploaded photos to the current page.
What to investigate first:


Frontend upload request
Check exactly what is being sent when user uploads from the page.
Verify:
file object
multipart/form-data handling
pageId
projectId if needed
company/business/org ID
auth/session headers
content-type handling
single vs multiple upload path


Backend upload endpoint
Check whether the page photo uploader is using:
a shared existing field note upload endpoint
or
a new page-specific upload endpoint


Likely issue:
The new Page flow is calling an endpoint or payload shape that does not match the existing upload service.


Storage step
Check whether the failure is happening:
before file reaches backend
during validation
during upload to storage
during database attachment to page
during thumbnail/metadata processing


Database attachment
Even if the file uploads to storage, the DB insert may fail when linking the uploaded asset to the page.
Check:
page exists
pageId is valid
foreign key constraint
organization/business scoping
createdBy
sort order
caption default
status/default fields


Likely root causes to test:


Wrong request format
The upload button may be sending JSON or malformed FormData instead of proper multipart upload.


Missing pageId or wrong param name
Backend may expect:
pageId
but frontend sends:
id
page_id
documentId
noteId


Auth or tenant context missing
The page was created under the current business, but the upload route may not be receiving the same tenant/business context.


Upload route not wired to new Pages model
The image may upload successfully in old walkthrough notes but fail in new manual pages because attachment logic still only supports old note entities.


File validation mismatch
PNG may be allowed in UI but blocked in backend validator or MIME-type parser.


Storage upload succeeds but DB link fails
This is common if:
page_photo row requires fields not being provided
page relation uses wrong table/model
organization mismatch blocks insert

Upload starts
Show uploading state
Store image successfully
Attach it to current page
Refresh photo grid immediately

Keep it professional and app-matching.
Do not show raw internal filenames unless in logs only.
