Most likely root causes to inspect first

1. Frontend query cache leakage
   If the app uses query caching, it may be reusing data under generic keys like:

* ["hours"]
* ["schedule"]
* ["requests"]

instead of employee-specific keys like:

* ["employee-hours", employeeId]
* ["employee-schedule", employeeId]
* ["employee-requests", employeeId]

If query keys are not user-specific, one employee can briefly see another employee’s cached data.

2. Session change not clearing cache
   When logging out and logging into another employee account, the app may not be clearing previous query cache/store state.

That causes old data to render until a refetch finishes.

3. API responses not tightly scoped
   Some employee endpoints may return broader company data and rely on frontend filtering.
   That is unsafe.

Employee APIs must return only the logged-in employee’s data from the backend.

4. UI renders old data before auth context resolves
   Pages may mount and render from stale state before the current employee identity is fully known.

5. Local state persistence leakage
   If some pages store last-loaded data in component/global state or local storage, it may survive login transitions and show the wrong records until refresh.

Required final behavior

1. Employee pages must be hard-scoped to current employee
   At all times, employee pages must only render data for:
   the currently authenticated employee

This applies to:

* Hours
* Schedule
* Requests
* Timesheets
* any employee-only lists

2. No stale previous-user flash
   When switching sessions or loading employee pages:

* do not render previous employee’s cached data
* show loading/skeleton if needed until current employee data is resolved

Better to show a loading state than the wrong person’s data.

3. Backend must enforce privacy
   Employee-facing endpoints must not return broader company records for frontend filtering.

They must enforce:

* current company
* current employee id
* current role permissions

Employee should only receive their own records from the server.
