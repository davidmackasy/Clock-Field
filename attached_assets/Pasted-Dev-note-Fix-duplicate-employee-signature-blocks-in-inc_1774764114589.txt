Dev note: Fix duplicate employee signature blocks in incident report export only

Objective

Fix the incident report display/export logic so the employee does not appear to sign twice.

Right now, when an admin sends a report to an employee, and the employee signs it in their account and adds a statement, the final admin print/download view still shows extra employee sign-off boxes at the bottom. That makes the report look repetitive and unprofessional.

This task is only about the incident report signature rendering logic and export layout for already-signed employee reports.

Critical instruction

Do not touch anything else.

Do not change report creation flow.
Do not change AI refinement.
Do not change branding.
Do not change logo behavior.
Do not change unrelated PDF logic.
Do not change routing.
Do not change permissions outside this exact signature display issue.
Do not refactor unrelated report code.

If anything outside this exact scope is needed, ask for approval first.

Main problem

Current behavior is wrong when this flow happens:

Admin creates incident report
Admin sends it to employee
Employee opens it in their account
Employee adds statement
Employee signs it in-app
Report comes back to admin
Admin prints/downloads it
Final exported report still shows:
the signed employee acknowledgement block
plus another employee acknowledgement placeholder/sign box at the bottom

That makes it look like the employee must sign twice.

Expected behavior

If the employee already signed the report in-app, the exported incident report must show only one employee acknowledgement/signature representation.

It should not show:

a signed employee block at the top
and another extra employee sign box at the bottom

Only the signed version should remain.

The remaining bottom sign-off area should only show the signatures that are still actually needed.

Required business rule

Employee signature rendering rule:

Case A
Employee has already signed in-app:

show the completed employee acknowledgement/signature once
remove/hide the extra employee acknowledgement placeholder box in the additional sign-off section

Case B
Employee has not signed in-app:

show the employee acknowledgement placeholder/sign box in the additional sign-off section
do not show a completed signed employee block because none exists yet

This logic must apply to the final printable/downloadable incident report.

Secondary display issue

The current signed block at the top is also not labeled professionally enough.

It should not just show the employee’s name at the top as if that is the section title.

Instead, the block should clearly read something like:

Employee Acknowledgement

Then inside the block:

signed by employee name
signed date
acknowledgement status
optional short line like “Signed electronically in Clockfield”

The section label should lead, not the employee name.

Professional display rule for signed employee section

If employee already signed in-app, show a formal signed acknowledgement block like this:

Employee Acknowledgement

Signed by: Mackasy
Role: Employee
Date: March 29, 2026
Status: Acknowledged

Or similar clean wording.

Do not make the employee’s name the section heading.
Do not duplicate that same employee in another blank sign box below.
