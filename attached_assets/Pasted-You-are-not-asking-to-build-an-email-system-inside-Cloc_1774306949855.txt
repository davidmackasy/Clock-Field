Dev Note: Add link preview metadata for public report links only

Critical instruction

Do not change, remove, refactor, or affect anything else in the app.
Do not build an email sending system.
Do not change Gmail, Outlook, or any third-party email app.
Do not touch report generation logic.
Do not touch stored photos.
Do not touch reviews, pay stubs, timesheets, subscriptions, or any unrelated feature.
Only improve the public report link so that when the link is pasted into supported email apps or messaging apps, it has a better chance of showing a preview thumbnail/card.

Actual goal

When a public Clockfield report link is copied and pasted into Gmail, Outlook, or similar places, the link should have proper preview metadata so supported apps can show:

thumbnail image
title
short description

This is similar to link preview behavior or unfurl behavior.

Important clarification

Clockfield cannot force every email client to show a preview.
Gmail, Outlook, and other apps decide whether they render a preview card or not.

What Clockfield can do is prepare the public report page correctly by adding proper metadata:

Open Graph tags
Twitter card tags
preview image URL
title
description

This is the correct implementation.

What needs to be implemented

For every public report page, add proper SEO / social preview metadata in the page head.

Required metadata
Add dynamic tags for each public report link:

og:title
og:description
og:image
og:url
og:type
twitter:card
twitter:title
twitter:description
twitter:image

Recommended values

og:title
Cleaning Service Report | [Business Name]

Example:
Cleaning Service Report | Master Commercial Cleaning Services

og:description
Completed cleaning report for [Location or Service Date]. View before and after photos and service details.

Example:
Completed cleaning report for Anchor Construction. View before and after photos and service details.

og:image
Use one strong preview image from the report.

Best choice:

first after photo from the report

Fallback order:

first after photo
first report photo
default Clockfield report preview image

og:url
The short public report URL

Example:
https://clockfield.com/r/BE5WBMJ

og:type
website

twitter:card
summary_large_image

Important image requirements

The og:image must be a publicly accessible absolute URL.
Not a relative path.
Not a protected/private URL.
Not a temporary local blob URL.

Recommended preview image behavior

Use the first after image as the main preview image because it looks more professional and shows finished work.

If possible, generate or use an optimized preview-sized image for metadata so the preview loads faster.
But do not alter or overwrite original stored photos.
Do not migrate old data.
Only use existing stored image URLs or safe derived thumbnail URLs if already supported.

Recommended dimensions
Try to make the preview image at least around:
1200 x 630
or another social-preview-friendly size if your system can provide it.

If not possible, use the existing first after image and let platforms crop it.

Important implementation detail

Because this is a dynamic public report page, the metadata must be server-rendered or rendered in a way crawlers can actually read.

Agent must check this carefully.

If the app is SPA-only and the meta tags are injected only after client-side JavaScript runs, many preview crawlers may fail to read them.

So the public report route should return actual metadata in the initial HTML response for that specific report.

This is critical.

Agent must verify:

whether the public report route is server-rendered
whether the metadata is present in page source before hydration
whether link preview bots can access it

If not, implement a safe server-side metadata response for public report routes only.
