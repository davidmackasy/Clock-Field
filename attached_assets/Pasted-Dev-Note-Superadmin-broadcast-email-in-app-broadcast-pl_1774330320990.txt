Mailgun implementation approach

Use Mailgun HTTP API for sending the email channel. Mailgun supports sending through the Messages API, supports batch sending to multiple recipients in a single API call, and also supports mailing lists. Batch sending currently allows up to 1,000 recipients per batch request. Mailgun also supports stored templates with template variables, which is useful for reusable welcome and broadcast emails.

For this feature, use one of these approaches:

Recommended now
Use Mailgun batch sending for broadcast emails if your business count is manageable and under batch limits per chunk.
This is simpler and safer than introducing Mailgun mailing lists into your app immediately. Mailgun’s docs state batch sending supports up to 1,000 recipients per batch request.

Do not use test mode in production. Mailgun test mode accepts the message but does not actually send it.

Use Mailgun templates if you want reusable branded emails for:

welcome email
broadcast email layout

Mailgun supports domain-level templates and variables through its Templates API and sending API.

Sending strategy

For broadcast emails:

fetch all eligible business emails
filter out null, empty, invalid, duplicate emails
chunk sends in safe batches
recommended batch size: up to 1,000 per Mailgun batch request, or smaller if you want tighter retry control. Mailgun’s docs specify a maximum of 1,000 recipients for batch sending.
record delivery attempts per recipient or per chunk depending on your implementation
do not block the UI waiting for every email to finish if your architecture supports background jobs
if you do not have a queue system, at least make the send operation fault-tolerant and log all outcomes

For welcome email:

single transactional send after successful business signup
send only once per new business creation
log result

Recommended technical pattern

Use a dedicated email service module with separate methods:

sendBroadcastEmailToBusinesses(...)
sendWelcomeEmailToBusiness(...)
optional shared helper sendMailgunMessage(...)

Do not copy-paste email code into controllers repeatedly.

Mailgun configuration requirements

Use the verified Mailgun sending domain and aligned From address.
Since you are already using Mailgun with mg.clockfield.com, keep email sending aligned to that domain unless a different production-approved sender domain is fully configured.

Recommended:

MAILGUN_DOMAIN=mg.clockfield.com
MAIL_FROM_BROADCAST=Clockfield noreply@mg.clockfield.com
MAIL_FROM_WELCOME=Clockfield noreply@mg.clockfield.com

Use the correct Mailgun API base URL for the region where the domain is hosted. Mailgun’s docs note that EU domains must use https://api.eu.mailgun.net instead of the default US base URL.

Do not put Mailgun into test mode in production. In test mode Mailgun accepts the request but does not actually send the email.
