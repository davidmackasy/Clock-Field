* Missed Shifts Today
* Late Clock-Ins Today
* Unread Business Messages
* Businesses Pending Payment

Define these carefully

Active Today
A business counts as Active Today if any of these happened today:

* Business admin logged in
* Any employee clocked in
* Any field note was created
* Any work log or task activity happened
* Any message was opened or sent inside the platform

Logged In Today
Count businesses where a business admin logged in today.

Employee Activity Today
Count businesses where at least one employee performed attendance or work activity today.

Missed Shifts Today
Count businesses with at least one employee marked missed today.

Late Clock-Ins Today
Count businesses with at least one late clock-in today.

Unread Business Messages
Count businesses with unread messages from Super Admin.

Businesses Pending Payment
Count businesses that signed up but have not completed subscription/payment access flow.

New Signups Today
Count businesses created today.

Graphs to add

1. Business Activity Last 7 Days

Current state to preserve
Current Field Note recording flow is working and users love it.
Do not break:

* start field note
* recording/transcript

Goal
Allow users to return to a field note and add after photos in a clean, controlled way.

New concept
Each field note can support photo phases:

* Before
* After

This must be optional.
Users can still create a field note with only before photos or only after photos if they want.
Do not force both.

Recommended UX
Option A
When a field note is completed, show actions:

* View Note
* Add After Photos
* Resume Note

Option B
Inside the field note details page, add:

* Add Before Photos
* Add After Photos

Best choice
Use Add After Photos on the completed field note detail screen.
That is simplest and least disruptive.

Rules
The original note remains one note.
Do not create a brand new note for after photos unless the architecture absolutely requires it.
Prefer a single field note with grouped photo sets.

Data model suggestion

Add:

* phase enum: before | after
* captured_at
* uploaded_by
* sort_order
* optional area/category

If there is already a photos table, extend it carefully instead of replacing it.

Viewing in admin
In the field note page, show clear tabs or grouped sections:

* All Photos
* Before
* After

For the visual layout inside the note detail page
Preferred layout:

* Before photos section first
* After photos section second

Alternative if there is a paired experience

* side by side compare mode for matching before and after groups

Do not force pairing if pairing data does not exist.
Start with grouped sections first.
That is safer and faster.

Public share behavior
If only before photos exist:

* show Before section only

If only after photos exist:

* show After section only

If both exist:

* show Before and After clearly labeled
* optionally show split layout or grouped blocks

Do not break existing public field note links.

7. FIELD NOTE RESUME OR PAUSE CONCEPT

Need
User may want to finish the note, then come back later and add after photos.

Safe implementation
Do not change the recording engine too much.
Do not create complex pause/resume recording logic unless necessary.

Recommended approach
Separate transcript recording state from photo phase management.

Simple flow

* User completes note as normal
* Later opens the note
* Clicks Add After Photos
* Uploads or captures after photos
* Saves
* Note now contains both phases

This avoids risky audio/transcript resume issues.

If resume is added
Only allow resume for photo capture or note additions.
Do not try to stitch multiple audio sessions together unless that logic already exists and is proven stable.
