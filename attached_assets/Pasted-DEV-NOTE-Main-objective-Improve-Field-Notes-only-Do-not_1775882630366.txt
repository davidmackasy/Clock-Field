Field Notes public link layout upgrade

Problem

The public Field Note document is too narrow on desktop.
It shows too few images per row.
Users have to scroll too far down to see all images.
Images from different areas are mixed together, which makes the report look unprofessional.

Required fix

On the public Field Note link, expand the content container on desktop so the page uses much more of the available width.
Do not leave large empty margins on the left and right.

Desktop public link requirements

The generated Field Note document should display at least 4 images per row on desktop.
Image rows should stretch properly across the document width.
Images should stay consistent in size and aligned cleanly.
The page should look like a professional gallery, not a narrow column.

Mobile public link requirements

On mobile, show 3 images per row where possible.
Do not leave mobile at 1 image per row for the photo sections.
Keep spacing tight but still readable.
Do not break image tap, preview, or scrolling behavior.

Implementation notes

Use responsive grid layout, not fixed narrow columns.
Target something like:
desktop xl/2xl = 4 columns minimum
tablet = 3 columns
mobile = 3 columns for compact gallery sections
If some document sections need larger hero images, that is okay, but standard photo sections must stay in a 3-column mobile layout.

Public Field Note transcript and notes must always be included

Problem

If a cleaner or manager is talking while recording, those notes must always appear in the generated Field Note properly.
Right now that behavior needs to be more reliable and visible.

Required fix

Every Field Note must preserve and surface transcript content when audio exists.
The public Field Note document must include:
the spoken transcript
AI-cleaned notes
section-level notes tied to the relevant photos or area when possible

If no transcript exists, clearly state that no transcript was recorded.
Do not hide that state.
Do not confuse users.

Important

Transcript content should not just exist in the backend.
It must render clearly inside the generated Field Note document and public link.

Required behavior

If audio exists:
show transcript summary
show cleaned notes
show section-specific observations

If no audio exists:
show a clear line such as:
“No audio transcript was recorded for this field note.”

Do not lose transcript text during document generation.
Do not drop transcript text when switching tabs between Document, Photos, and Transcript.
Do not remove transcript content from the public link.

AI auto-grouping of images by area

Problem

All images are being mixed together.
Washroom images should not sit beside kitchen images inside one generic block.
Users need clear grouped sections.

Required fix

When generating the Field Note document and public link, automatically group images into area-based sections.

Examples of sections

Washroom
Kitchen
Hallway
Office
Entrance
Break room
Storage room
Floor area
Common area
Exterior
Mechanical or utility room
Other or Unclassified

How it should work

Use image analysis on the Field Note photos.
Detect the likely area shown in each image.
Group related photos into the same block.
Generate a section title for each block.
Place related notes and transcript snippets inside the same block when possible.

Example

If images mostly show toilets, sinks, mirrors, stalls, soap dispensers:
put them under Washroom

If images show stove, fridge, sink, prep table, grease, kitchen equipment:
put them under Kitchen

If images show corridor flooring, doors, long passageways:
put them under Hallway

Important fallback behavior

Do not force bad classifications.
If confidence is low, place photos into General Facility Overview or Other.
But do not dump everything into one block if the model can clearly separate them.

Required output structure for the document

Section title
Short area summary
Related transcript or notes
Image grid for that area

This applies to:
the public Field Note link
the generated Field Note document in admin

Quote flow improvement from Field Notes

Scope boundary

Only improve the quote flow that starts from Field Notes.
Do not redesign the full invoicing system.
Do not touch other unrelated quote flows unless they depend directly on this Field Note quote feature.

Problem

Too many manual fields.
Not enough AI help.
The quote does not intelligently generate scope summary or pricing help.
Users should not have to enter everything manually.

Required fix

When a user clicks Turn into Quote from a Field Note, the system should prefill as much as possible from the Field Note.

Auto-prefill from Field Note

Client name if known
Site name
Address if known
Detected facility type
Detected service areas from the photos
Detected condition level from the images and notes
Suggested scope summary
Suggested service frequency
Suggested labor estimate
Suggested first-pass pricing estimate

Manual inputs should be reduced to only the most important missing fields.

New minimal quote input flow

Step 1
Prefill what already exists from the Field Note

Step 2
Ask only the missing essentials, such as:
square footage
cleaning frequency
estimated hours per visit
special services if needed
location confirmation
any access limitations

Step 3
Generate:
scope summary
service recommendation
estimated labor hours
suggested quote price
client-facing quote text

Important

Do not show all photos in the quote.
Only show a limited number.

Quote photo rule

Show only the first 6 most relevant photos in the quote.
Not all photos.
Use representative photos only.

AI-assisted quote logic

Required behavior

The quote generator must do more than copy fields.
It should produce:
a clean scope summary
recommended cleaning tasks
estimated effort
suggested price range
final suggested quote total

Pricing logic recommendation

Do not rely only on raw AI freeform output.
Use structured calculation.

Use a hybrid approach:
AI extracts the scope
system calculates price from rules
AI writes the summary cleanly

Suggested inputs to pricing engine

square footage
service frequency
estimated labor hours
facility type
condition severity from photos
location
special tasks
one-time deep clean or recurring
number of key areas detected

Suggested output

Estimated labor hours
Suggested visit duration
Suggested rate per visit
Suggested weekly or monthly total if recurring
Suggested one-time total if one-off

Very important

Do not make live browsing of outside market pricing the only pricing source.
That will make quoting unstable and inconsistent.
Instead:
use internal configurable pricing logic first
allow optional location-based pricing multiplier
allow admin override
allow future market comparison module later if needed

Best safe implementation

Create admin-configurable quote settings:
base hourly rate
city or region multiplier
deep-clean multiplier
washroom multiplier
kitchen or grease multiplier
recurring discount rules
minimum visit charge

Then use AI to estimate scope and calculator logic to turn that into price.

This is the correct way to keep it accurate, editable, and reliable.
