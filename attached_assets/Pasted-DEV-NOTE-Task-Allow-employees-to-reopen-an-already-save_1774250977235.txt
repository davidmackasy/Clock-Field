DEV NOTE

Task:
Allow employees to reopen an already saved work item and keep adding more before/after photos until the full work log is submitted.

Main instruction:
Do not break, remove, refactor, or affect anything else that is currently working.
Do not change admin workflow, report delivery, submission flow, or existing work log structure outside of this exact improvement.
This must be a safe employee-side workflow enhancement only.
Keep the same feel of the app.
Do not redesign the entire page.
Only improve the saved work-item editing flow so employees can go back into an existing area and continue adding photos before final submission.

Goal

Right now, when an employee adds a work area and saves it, that item becomes too final too early.
The employee cannot go back into that saved item and continue adding more before photos or after photos.
That causes a bad workflow because:

* one area may need multiple photos
* before and after photos may be taken at different times
* employees should not be forced to create another area just to add more pictures for the same place

Required fix:
Before the full work session is submitted, employees must be able to:

* tap an already saved work item
* reopen it
* see existing details and existing photos
* add more before photos
* add more after photos
* optionally update notes
* save changes back to that same work item

Important:
This must only be allowed while the session is still open or draft.
Once the employee submits the full work session, the item should become locked as it already does, unless you already support a separate edit-after-submit workflow.

Business rule

A saved work item is not finished just because it was created.
A saved work item should remain editable until the employee submits the full work session.

That means:

* Create work item
* Add one or more before photos
* Save item
* Continue working
* Reopen same item later
* Add after photos or more before photos
* Save again
* Repeat as needed
* Submit full work session
* Then lock editing

This is the correct workflow.

1. Current problem

Current behavior:

* Employee taps Add Area
* Employee selects section and area
* Employee adds one photo
* Employee saves work item
* Work item appears in Active Session
* But employee cannot reopen that same item and continue adding more pictures

Why this is a problem:

* cleaners often take before photos first and after photos later
* one room may need multiple photos
* one area may need multiple angles
* users are forced to create duplicate areas just to keep adding photos
* this makes the final report confusing for admin and client
* before/after grouping becomes messy

Example of the problem:
Employee creates:
Floors > Main Floor
Adds one before photo
Saves

Later they finish cleaning and want to add two after photos to that same Floors > Main Floor item.
Currently they cannot properly continue that same item, so they are pushed into adding another area or another record.
That breaks the structure of the report.

2. Required new behavior

For employee account only:
Any saved work item inside the active session must remain editable until the entire work session is submitted.

Required behavior:

* Employee can tap a saved work item card in Active Session
* Existing modal or editor opens again in edit mode
* Existing data is loaded into the form
* Existing photos are shown
* Employee can add more before photos
* Employee can add more after photos
* Employee can keep notes or update notes
* Employee can save changes without creating a duplicate item
* All new photos remain attached to that same work item

Important:
Do not replace the existing workflow.
Extend it.

So:

* Add Area still creates a new work item
* But saved items can now be reopened and updated before submission

This change applies only to:

Do not apply this change to:

* admin completed report viewer unless it already reads all photos safely

6. Photo behavior change

This is the most important part.

Right now, the item behaves too much like one-photo-and-done.
That must change.

New required rules:
Before submission, each work item must support:

* multiple before photos
* multiple after photos

Employees must be able to:

* add another before photo later
* add another after photo later
* delete an existing photo before submission if needed
* view thumbnails of already attached photos
* keep adding photos over time to the same item

Important:
Do not force one before and one after only.
Allow multiple photos in each category.

Recommended structure:
Work item

* before_photos: array
* after_photos: array

Not:

* before_photo: single item
* after_photo: single item

If the backend already supports arrays, use that.
If not, extend carefully without breaking existing records.

Backward compatibility:
If older work items only have one before or one after image, they should still render properly.
Treat single existing values as the first item in the array where needed.

7. Editing rules

Allowed before session submission:

* add before photos
* add after photos
* update notes
* remove photos
* possibly change section/area only if safe

Recommended rule for section/area:
If changing section/area could break report grouping, keep section and area read-only once item is created.
Let employee update notes and photos only.

This is safer.

Best recommendation:
After item creation:

* section = locked
* sub-area = locked
* notes = editable
* before photos = editable
* after photos = editable

Reason:
This avoids a saved Floors item suddenly being changed into Washroom and causing mismatched data.

8. Submission lock rule

Very important:
Editing must stop once the full work session is submitted.

Required rule:
If session status is draft or active:

* work item editable

If session status is submitted:

* work item locked
* no more adding photos
* no more changing notes
* no more deleting existing photos

History items should remain read-only as they already should be.

9. Data model expectations

Keep this safe and backward compatible.

Recommended work item structure:

* id
* session_id
* section_id or section_name
* area_id or sub_area_name
* notes
* before_photos []
* after_photos []
* created_at
* updated_at
* status

If your current structure already has:

* before_photo
* after_photo

Then safely migrate or normalize to support:

* before_photos []
* after_photos []

Backward-safe handling:
When reading older records:

* if before_photo exists and before_photos is empty, map it into before_photos[0]
* if after_photo exists and after_photos is empty, map it into after_photos[0]

Do not break old reports.
