What is causing the error

One or more Select items are using an empty string as the item value, like this:

<SelectItem value="">Select something</SelectItem>

This is invalid.

In this Select system, empty string is reserved for clearing the current selection and showing the placeholder.
That means every SelectItem must have a real non-empty value.

Correct rule

SelectItem must never use value=""
placeholder text must be shown using SelectValue placeholder="..."
unselected state can still use "" in component state if needed
the dropdown options themselves must always use non-empty values

What to search for

Search only in the page/components involved in this runtime error first.

Look for patterns like:

<SelectItem value="">
value={""}
<option value="">

Most likely locations:

report type select
client select
cleaner/employee select
severity select
status select
any new Reports page dropdowns

Primary fix pattern

Wrong:

<Select value={reportType} onValueChange={setReportType}>
  <SelectTrigger>
    <SelectValue placeholder="Select report type" />
  </SelectTrigger>
  <SelectContent>
    <SelectItem value="">Select report type</SelectItem>
    <SelectItem value="incident">Incident Report</SelectItem>
    <SelectItem value="issue">Issue Report</SelectItem>
  </SelectContent>
</Select>

Correct:

<Select value={reportType} onValueChange={setReportType}>
  <SelectTrigger>
    <SelectValue placeholder="Select report type" />
  </SelectTrigger>
  <SelectContent>
    <SelectItem value="incident">Incident Report</SelectItem>
    <SelectItem value="issue">Issue Report</SelectItem>
  </SelectContent>
</Select>

Optional/unselected state pattern

It is okay for the component state to be empty when nothing is selected.

Example:

const [reportType, setReportType] = useState("");

Then:

<Select value={reportType} onValueChange={setReportType}>
  <SelectTrigger>
    <SelectValue placeholder="Select report type" />
  </SelectTrigger>
  <SelectContent>
    <SelectItem value="incident">Incident Report</SelectItem>
    <SelectItem value="issue">Issue Report</SelectItem>
    <SelectItem value="damage">Damage Report</SelectItem>
  </SelectContent>
</Select>

If the state is "", the placeholder will show.
That is correct.
Do not create a fake empty SelectItem.

If a “None” option is needed

If the UI truly needs a user-visible “None” or “Unassigned” option, it must still use a non-empty value.

Use something like:

<SelectItem value="unassigned">Unassigned</SelectItem>

or

<SelectItem value="none">None</SelectItem>

Then handle that explicitly in code.

Example:

onValueChange={(value) => {
  setAssignedEmployee(value === "unassigned" ? "" : value);
}}

Important:
Only do this if the UI actually needs an explicit selectable “None” option.
Otherwise, rely on placeholder + empty state.

Safe implementation guidance

For all affected selects, use this safe structure:

<Select value={selectedValue} onValueChange={setSelectedValue}>
  <SelectTrigger>
    <SelectValue placeholder="Select an option" />
  </SelectTrigger>
  <SelectContent>
    {options.map((option) => (
      <SelectItem key={option.id} value={option.id}>
        {option.label}
      </SelectItem>
    ))}
  </SelectContent>
</Select>

If options are dynamic, validate them before rendering.
Do not allow undefined, null, or empty-string values into SelectItem.

Safe dynamic rendering example

{options
  .filter((option) => option.id && option.id.trim() !== "")
  .map((option) => (
    <SelectItem key={option.id} value={option.id}>
      {option.label}
    </SelectItem>
  ))}

Only add filtering if needed to stop bad dynamic values from being rendered.
Do not rewrite the full data source unless necessary.
