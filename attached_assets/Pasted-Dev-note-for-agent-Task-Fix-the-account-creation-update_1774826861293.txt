Dev note for agent

Task

Fix the account creation/update logic so a user can use a normal name and email combination without triggering a false duplicate error.

Example that must work:

First name: David
Last name: Mackasy
Email: davidmackasy@gmail.com

Using a person’s name inside their email is normal and must not be treated as a uniqueness conflict.

Important
Only focus on this issue.

Do not touch:

attendance
employee hours
payroll
schedules
reports
signatures
email sending flows
auth behavior unrelated to this specific duplicate-validation issue
any unrelated database logic
anything else in the system

Problem

Right now the system appears to be throwing a duplicate error like:
users_email_unique
or a similar uniqueness validation error in situations where the name and the email are naturally related.

That is incorrect behavior.

A person’s:

first name
last name
username/display name
and email

can obviously contain the same words. That does not mean they are duplicates in the wrong way.

What needs to be fixed

The system must only enforce uniqueness on the correct field.

That means:

email uniqueness should only be checked against email
username uniqueness should only be checked against username if username is actually a unique field in your system
first name and last name must not be compared against email for uniqueness
display name/full name must not be compared against email for uniqueness

Examples that must be allowed

Name: David Mackasy
Email: davidmackasy@gmail.com
Username: davidmackasy
Email: davidmackasy@gmail.com
Name: Gift Banda
Email: giftbanda@gmail.com

Those are normal and valid.

Likely issue to inspect

Please inspect the actual signup/create-user/update-user validation path carefully.

Possible causes:

Wrong frontend validation logic
A check may be incorrectly blocking values because email contains first name, last name, or username.
Wrong backend validation logic
The server may be performing an incorrect uniqueness comparison across the wrong fields.
Wrong payload mapping
The email field may accidentally be getting copied into username, or username into email, causing a conflict.
Wrong database write/update logic
During create or update, the same value may be written into multiple unique columns unintentionally.
Bad duplicate-check query
The query may be using OR conditions incorrectly, such as:
email equals value
username equals value
without checking which field is actually being validated
Update flow not excluding current record
If editing an existing user, the uniqueness check may be comparing the record against itself and falsely failing.

What the correct behavior should be

Email

must only be unique among emails

Username

only enforce uniqueness if the system truly requires unique usernames
if username is optional, handle that safely
if username is auto-generated, make sure it does not incorrectly collide with email logic

Names

first name and last name do not need uniqueness
full name does not need uniqueness
names can resemble emails and that is fine

Correct validation rules

Email validation

valid email format
compare only against existing email column
case-insensitive comparison if your system normalizes email
trim whitespace

Username validation

only if username exists in your system as a unique identifier
compare only against username column
do not compare username to email as a uniqueness conflict
if username equals email local-part, that is allowed unless your product explicitly forbids it

Name validation

required/non-required based on current business rules
no uniqueness enforcement against email
no uniqueness enforcement against username unless intentionally designed, which is not recommended here
