DEV NOTE

Feature name:
Employee Pay Stub System for Cloud Clock Field

Priority:
High

Main instruction:
Do not break, remove, refactor, or change anything else that is already working in Cloud Clock Field.
Do not change existing attendance, timesheet, payroll, employee profile, or admin workflows unless it is strictly required for this pay stub feature.
This must be added as a safe extension that reads from existing systems and syncs with them.
All current working logic must stay intact.

Goal

Add a real pay stub system that connects attendance, timesheets, payroll, employee pay settings, deductions, and benefits into one accurate payroll record.

The pay stub must:

* Only become visible to an employee after admin confirms that the employee has been paid for that payroll period
* Pull accurate values from the system
* Let admin review and adjust pay-stub-specific payroll values before finalizing
* Allow employee to view and download past pay stubs from their account
* Show earnings, hours, deductions, benefits, taxes, net pay, pay period, and company details
* Keep a locked historical record after finalization so old pay stubs cannot be accidentally changed

Important business rule

A pay stub is not the live timesheet.
A pay stub is a payroll snapshot generated from the approved payroll data for a specific employee and period.

That means:

* Attendance feeds timesheets
* Timesheets feed payroll calculations
* Payroll feeds pay stub draft
* Admin reviews pay stub draft
* Admin confirms employee has been paid
* System finalizes pay stub
* Employee can then view/download it

This avoids changing historical attendance or timesheet records when admin only wants to fix a pay stub number before release.

1. Core system behavior

New workflow

Step 1:
Attendance and clock-in/clock-out data continue working exactly as they already do.

Step 2:
Timesheets continue working exactly as they already do.
Approved timesheets remain the base source for worked hours.

Step 3:
Payroll uses approved timesheets plus employee pay settings to calculate gross pay, deductions, benefits, taxes, and net pay.

Step 4:
Admin opens Payroll > Pay Stubs and generates a draft pay stub for a selected payroll period and employee.

Step 5:
Before finalizing, admin can adjust pay-stub-level values only, such as:

* Regular hours
* Overtime hours
* Bonus
* Reimbursement
* Manual deduction
* Vacation payout
* Sick payout
* Holiday pay
* Other earnings line items
* Other deduction line items

Step 6:
The system recalculates totals immediately after each adjustment.

Step 7:
Admin marks employee as Paid / Confirmed Paid.

Step 8:
Once confirmed paid, pay stub status changes to Finalized and becomes visible in the employee portal.

Step 9:
Employee can open, view, and download PDF pay stub.

Very important:
Admin adjustments inside pay stub draft must not rewrite original attendance records.
Do not overwrite original timesheet data unless admin explicitly uses an existing separate payroll correction workflow.
Pay stub adjustments should be stored as pay stub adjustment records.

5. Status logic

Pay stub status flow

draft
System-generated, editable by authorized admin only

reviewed
Admin reviewed but not yet finalized

finalized
Locked payroll snapshot created

paid_confirmed
Admin explicitly confirmed employee was paid

published
Visible to employee and downloadable

voided
Invalidated pay stub, only for correction workflows

Visibility rule

Employee must only see pay stubs when:

* status is paid_confirmed or published
* employee_visible_at is not null

Recommended simplified release rule:
Once admin clicks Confirm Paid, automatically:

* finalize if not finalized
* publish to employee
* create PDF
* set employee_visible_at

8. Adjustment rules

This part is very important.

Allowed admin edits before finalization:

* Hours on pay stub lines
* Rates on pay stub lines if authorized
* Add/remove earning line items
* Add/remove deduction line items
* Add notes
* Override calculated values with reason

Not allowed:

* Editing published pay stub without correction process
* Changing original attendance silently
* Changing approved timesheet silently through pay stub editor
* Editing historical pay stubs without audit log

Correction flow

If a published pay stub is wrong:

* Do not directly overwrite it
* Create correction workflow:

  * Void original if allowed by business rule
  * Create corrected draft
  * Finalize corrected version
  * Republish corrected pay stub
  * Keep audit trail

9. Calculation engine requirements

The calculation engine must combine:

* Employee pay type
* Regular hours
* Overtime rules
* Salary rules
* Deductions
* Benefits
* Taxes if configured
* Manual admin adjustments

Hourly employee logic

* regular_hours × hourly_rate
* overtime_hours × overtime_rate
* add any extra earnings
* subtract deductions
* net pay = gross pay - total deductions

Salary employee logic

* salary-based period amount
* add extra earnings
* subtract deductions
* net pay = gross pay - total deductions

Important:
Create a payroll calculation service that centralizes pay stub math.
Do not scatter pay formulas across frontend components.

Recommended service methods:

* generatePayStubDraft(employeeId, payRunId)
* calculatePayStubTotals(payStubId)
* applyPayStubAdjustment(payStubId, payload)
* finalizePayStub(payStubId)
* confirmPayStubPaid(payStubId)
* publishPayStub(payStubId)
* generatePayStubPdf(payStubId)

22. Recommended business-safe rules

To keep the system clean and prevent mistakes:

Rule 1
Do not let admin edit published pay stubs directly.
Use correction flow.

Rule 2
Require confirmation modal for Confirm Paid action.

Rule 3
Require reason for manual overrides on calculated fields.

Rule 4
Lock pay stub totals after finalization unless correction mode is used.

Rule 5
Always keep a full snapshot of employee pay settings and company details at the time of pay stub generation, so future company profile edits do not alter old pay stubs.
