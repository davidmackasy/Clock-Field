DEV NOTE: Add Temporary Password Flow For Super Admin Created Businesses

Project: ClockField
Area: Super Admin > Business Details Modal
Related flow: Super admin creates company / grants trial access / temporary access override

Important:
Do not break or affect anything else.
Do not change subscription logic.
Do not change trial access logic.
Do not change temporary access override logic.
Do not change existing business records.
Do not change cleaner, employee, schedule, attendance, payroll, work log, supplies, publications, settings, or messages.
Only add the temporary password setup flow for super-admin-created businesses.

Goal

When a super admin creates a business account manually, the system should generate a temporary password for the business admin.

The business admin should be able to log in using:

Email
Temporary password

After first login, they must be forced to create their own password before accessing the app.

This is required because super admin-created businesses may not have created their own password during signup.

Current missing piece

The modal already shows:

Trial Access
Temporary Access Override
Resend Setup Email
Extend Trial
Extend Access
Remove Access

But it does not clearly support:

Temporary password generation
Temporary password reset
First-login password change requirement

Add this safely.

Required behavior

When super admin creates a company:

Create the business admin user.
Generate a temporary password.
Save only the hashed password in the database.
Mark the account as requiring password change.
Send setup email with login instructions.
On first login, force the user to create their own password.
After password is changed, remove the temporary password requirement.

Temporary password rules

Generate a secure temporary password.

Example format:

CF-9K7M-2Q8X

Requirements:

At least 10 characters
Includes letters and numbers
Easy enough to type
Unique per generated password
Expires after a set period if possible

Recommended expiration:

7 days from generation

If the temporary password expires, super admin can generate a new one.

Database changes

Use additive migration only.

Do not remove or rename existing fields.

Add fields to business admin user table or auth user profile table:

temporary_password_required boolean default false
temporary_password_created_at timestamp nullable
temporary_password_expires_at timestamp nullable
temporary_password_last_sent_at timestamp nullable
created_by_super_admin boolean default false

Optional:

temporary_password_reset_count integer default 0

Important:
Never store the plain temporary password.
Only store the hashed password using the same secure password hashing method used by the app.

Only include the temporary password in the email if a new temporary password was generated in that action or if the backend has it available only during that generation request.

Do not try to read the password later from the database.

Backend API changes

Add endpoints safely:

POST /api/super-admin/businesses/:businessId/generate-temporary-password

Purpose:
Generate a new temporary password for the main business admin.

Process:
Validate requester is super admin.
Find business.
Find primary admin user.
Generate secure temporary password.
Hash password.
Update user password hash.
Set temporary_password_required = true.
Set temporary_password_created_at = now.
Set temporary_password_expires_at = now + 7 days.
Increment temporary_password_reset_count.
Return temporary password once in response.

POST /api/super-admin/businesses/:businessId/send-setup-email

Purpose:
Send setup email.

Important:
This endpoint should either:

Option A:
Require a newly generated temporary password in the same request.

Or Option B:
Internally generate a new temporary password before sending setup email.

Preferred:
Use Option B to avoid sending old or unavailable passwords.

PATCH /api/auth/change-temporary-password

Purpose:
Allow business admin to replace temporary password after first login.

Input:
currentTemporaryPassword
newPassword
confirmPassword

Process:
Verify user is logged in.
Verify temporary_password_required = true.
Validate new password.
Update password hash.
Set temporary_password_required = false.
Clear or keep timestamp history.
Redirect user to dashboard after success.

Security requirements

Never store temporary password as plain text.
Never log the temporary password.
Never expose temporary password in normal business details API responses.
Only return temporary password once immediately after generation.
Only super admin can generate or resend setup temporary passwords.
Temporary password should expire after 7 days if possible.
If expired, login should show:
Your temporary password has expired. Please contact your administrator for a new setup password.

Do not expose password details to other admins.
