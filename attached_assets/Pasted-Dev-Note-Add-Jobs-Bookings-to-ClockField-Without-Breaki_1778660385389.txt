Dev Note: Add Jobs + Bookings to ClockField Without Breaking Existing Features or Crowding the App
Goal
Add a premium Jobs and Bookings system to ClockField so cleaning and service businesses can:
Schedule jobs
Assign workers
Track job status
Avoid missed cleans
Avoid double bookings
Let clients request bookings through a form
Connect each job to photos, notes, Field Notes, Work Reports, and client report links
Keep the app simple and not crowded with too many pages
This must be done without changing, breaking, replacing, or removing anything that already works in ClockField.
Important correction
The app is ClockField.
Do not rename anything to Clockify.
Core safety rule
Do not touch or rebuild existing working systems.
Do not change:
Existing Schedule
Existing Attendance
Existing Clock In
Existing Clock Out
Existing Clients
Existing Employees
Existing Field Notes
Existing Work Log
Existing Work Reports
Existing Photo Uploads
Existing Public Client Report Links
Existing Payroll
Existing Training Hub
Existing Publications
Existing Forms
Existing Settings
Existing time zone logic
This update must be added as a safe layer that connects to existing systems.
If the new Jobs and Bookings feature is disabled, ClockField must work exactly like it works today.
Feature flag
Add this behind a feature flag:
enable_jobs_bookings
When disabled:
No new job or booking UI appears.
All current ClockField pages work the same.
When enabled:
Jobs and Bookings appear inside existing areas without crowding the navigation.
Main concept
ClockField should feel like one place where service businesses manage the full workday.
Simple product flow:
Client books or requests service.
Admin reviews the booking.
Admin turns it into a job.
Admin assigns worker.
Worker clocks in like normal.
Worker starts work or Field Note like normal.
Worker takes photos and notes like normal.
Admin reviews the work.
Client gets one clean report link.

Main definitions
Regular Schedule
This is the worker’s shift or normal work time.
Example:
Fortune works Monday to Friday from 5 PM to 10 PM.
Job
This is the actual service work that needs to be completed.
Example:
Clean ABC Office on Friday from 6 PM to 8 PM.
Booking Request
This is a request from a client or new customer.
Example:
A client fills out a form asking for office cleaning next Tuesday.
Attendance
This remains the source of truth for clock-in, clock-out, and hours worked.
Field Notes / Work Reports
These remain the source of truth for photos, notes, proof, and client updates.
Public Client Link
This remains the way clients receive proof of work.
Core rule
Jobs connect to existing systems.
Existing systems do not depend on Jobs.
That means:
Attendance works without a job.
Schedule works without a job.
Field Notes work without a job.
Work Reports work without a job.
Public report links work without a job.
But a job can optionally connect to attendance, Field Notes, Work Reports, and report links.

Feature 4: Double booking protection
When admin assigns a worker to a job, check for conflicts.
Warn if:
Worker already has a job at the same time.
Worker already has a regular schedule conflict.
Worker is already assigned to another client/location.
Location already has another job at that time.
Do not hard-block the admin.
Show warning:
This worker already has another job during this time.
Allow admin to:
Change time
Choose another worker
Save anyway
This helps avoid double bookings without breaking flexibility.
